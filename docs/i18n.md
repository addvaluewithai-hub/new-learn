# Languages

Every text the interface shows lives in one file per language:
`apps/platform/src/i18n/locales/<code>.json`. Arabic (`ar.json`) is the source; the other
files have exactly its keys. Lesson content (scenes, questions, course titles) is not here:
it is written in its own language and stays as written.

## Adding a language

1. Copy `en.json` (or `ar.json`) to `<code>.json`, where `<code>` is a language code such as
   `it`, `pt-BR` or `zh-Hant`.
2. Translate the values. Keep every key, every `{placeholder}` and the shape of lists.
3. Run `npm run i18n`. It checks the file against `ar.json` and refreshes the server's
   messages. Fix what it lists until it reports 0 problems.

That is all: the language appears in the pickers by its own name (from the browser's
`Intl.DisplayNames`), right-to-left languages turn the layout around by themselves (`dirOf`
in `core.ts`), and the app loads the file only when someone picks it.

## Which language a visitor sees

`?lang=fr` in any address, then the choice saved on this device, then the browser's
languages, then Arabic. The pickers (site bar, site foot, settings) save the choice. The app
sends it to the server as `x-nl-lang`, so error messages and Nova follow it.

## The file

- Keys are grouped by feature (`site`, `landing`, `auth`, `studio`, `runtime`, `server`…),
  camelCase, nested as deep as reads well. A group may not have a key named `other`.
- `{name}` is a placeholder: `"أهلًا يا {name}"`. Numbers are formatted for the language.
- A plural is a group of Intl plural forms with `other` required:
  `{"one": "سؤال واحد", "two": "سؤالين", "few": "{count} أسئلة", "other": "{count} سؤال"}`.
  Each language uses its own forms (English `one`/`other`, Chinese `other` only).
- Lists (FAQ, legal sections) are JSON lists; every language has the same number of items.
- A link or bold part inside a sentence is a placeholder filled with an element by `<Rich>`:
  `"راسلنا على {email}"`.
- `runtime` holds the lesson player's texts (the runtime package keeps the same Arabic as
  its defaults in `packages/lesson-runtime/src/text.ts`; a check keeps the two equal).
- `server` holds what the server says: errors and statuses. Server code throws keys under it.
- `build.steps` holds the course builder's progress lines; the worker sends a step key.

## In code

```tsx
import { useI18n } from '../../i18n';
const { t, list, locale, dir } = useI18n();
<h1>{t('teach.title')}</h1>
<p>{t('catalog.lessons', { count: 3 })}</p>
{list('site.faq').map((item) => …)}
<Rich k="site.support.lead" parts={{ email: <a href="mailto:…">…</a> }} />
```

- Keys are typed from `ar.json`: a misspelled or missing key fails the typecheck.
- Call `t` while rendering, never at import time: module constants hold keys
  (`name: 'looks.chalk.name'`) and components call `t(look.name)`.
- Outside React (request helpers), `t` and `currentLocale()` from `i18n/index.ts` work too.
- Never build a sentence from pieces; give the translator the whole sentence with
  placeholders.
- Layout uses logical CSS (`inset-inline-start`, `margin-inline-end`, `text-align: start`) so
  it turns with the direction. Arrows are texts too: `common.forward` (a link onwards: `←` in
  Arabic, `→` in English), `common.back` and `common.backLink` (the arrow before a "back to…"
  link: `←` in both, as the Arabic pages have always drawn it).
- Server: `throw new HttpError(404, 'course.notFound')`; the error boundary translates it with
  `serverText(localeOf(request), key)`.

## Checks

`npm run i18n -- --check` (and `apps/platform/tests/i18n.test.ts`) fails on a missing or
extra key, a changed placeholder, a list of another length, an empty text, or a stale server
catalogue. `tests/i18n-browser.mjs` opens the site and the app in every language and checks
the direction and that no interface text is left in another language.
