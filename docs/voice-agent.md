# Voice agent and builder

Owner direction, 2026-10-27. Put on headphones, press one big button, and talk. Nova knows the
platform: it continues the learner's course where they left off, runs the lesson in whatever
way suits them, and can build a new course with them. The platform is paid from the start; a
free tier comes later. Tasks and rounds: docs/tasks/voice.md and docs/tasks/rounds.md.

## Principles

1. **Nova talks and calls tools; it does not do the work itself.** The live voice model
   (Gemini Live) is fast and cheap per minute, but weak at long structured writing.
2. **Every action is one function, written once.** Each is used by three callers:
   - the app's buttons;
   - the teacher's own AI through the connector (`/mcp`);
   - Nova.
3. **Heavy work runs as a job on our builder.** Building a course, writing a board and fixing
   notes are done by Codex CLI or Claude Code running on our server. They call the same `/mcp`
   tools, so every result is validated, saved as a draft and reviewed like any other.
4. **Simple wins.** Add a tool before adding an agent. The bridge carries requests, files,
   progress and results; it never decides what the user meant. (This is the rule
   wp-slack-agent already follows.)
5. **Honest state.** A skipped question is not a mastered goal. Nothing is published without
   the teacher's review. No "done" until the tool says so.

## Shape

```text
learner/teacher ── headphones ──► Nova (Gemini Live): talks, calls tools
                                    │
                 ┌──────────────────┴──────────────────┐
           fast tools (ms)                      heavy tools (jobs, minutes)
  continue course, open lesson,           start_build, build_status, fix_notes
  skip / reveal / repeat / back,                    │
  question style, my progress             builder worker (our server):
                 │                        Codex CLI or Claude Code, sandboxed,
                 │                        only tool = our /mcp as that user
                 └──────────────────┬──────────────────┘
                      Neon: courses, drafts, progress, jobs
```

## Nova's three modes

Gemini Live fixes a session's tools and instructions when it opens. Switching mode therefore
reopens the session in about a second with the same voice and a short summary of the
conversation so far. The lesson session stays as it is today: its context is rebuilt on the
server from trusted lesson files.

| Mode   | Example                                | Tools                                                       |
| ------ | -------------------------------------- | ----------------------------------------------------------- |
| Home   | "Continue physics", "where am I?"      | my courses, continue course, open lesson, my progress       |
| Lesson | "Skip this question", "just tell me"   | next, back, repeat, go to scene, skip, reveal, answer       |
| Build  | "Make me a course on…", "use this PDF" | outline, web search, read upload, start_build, build_status |

## The lesson stops being hard-coded

The lesson stays content: scenes, steps and questions. How it is walked through becomes the
learner's setting, and Nova carries it out with tools:

- **Questions:**
  - when: after every scene (today), at the end only, or none;
  - more on request ("give me more questions"), from the question bank (Q5) or generated by a
    cheap text model grounded in the lesson.
- **Skip:** always allowed. It is recorded as skipped and counts nowhere towards mastery.
- **Reveal the answer:** shows the model answer and records "revealed", not "correct".
- **Repeat, go back, go to a scene:** the runtime already has `next` and `goTo`; we add `skip`
  and `reveal` to `LessonController`.

## The builder: reuse wp-slack-agent

`addvaluewithai-hub/wp-slack-agent` already runs Codex CLI on a VPS for a client in production.
Its runtime does what the builder needs, so we port it instead of starting over:

| wp-slack-agent                      | What it does                                                                                       | In New Learn                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `src/codex/runner.js`               | `codex exec --json` / `exec resume <thread>`, sandbox `workspace-write`, images with `-i`, timeout | as is                                                    |
| `src/codex/events.js`               | JSON events → progress titles ("Creating the draft…") and the final text                           | titles for our tools; Nova reads them aloud              |
| `src/codex/recovery.js`             | one retry after a dropped stream, with an idempotent recovery prompt                               | as is; our tools are idempotent by course and lesson ids |
| `src/codex/errors.js`, `usage-*.js` | friendly errors; the account's usage windows                                                       | as is; feeds usage limits per plan                       |
| `src/codex/skills.js`               | copies versioned skills into `CODEX_HOME/skills` at start                                          | authoring guide and board rules as skills                |
| `src/state/queue.js`, `store.js`    | one run at a time per conversation; thread → Codex session map                                     | per course build; "change lesson 2" resumes it           |
| `src/web/workflow-jobs.js`          | async job: id, queued/running/complete/error                                                       | build jobs, stored in Neon instead of memory             |
| `deploy/codex-config.toml`          | `approval_policy = "never"`; MCP server pre-approved because its tools are narrow                  | `[mcp_servers.newlearn]` → our `/mcp`                    |
| Slack transport                     | messages in, one reply out                                                                         | replaced by the app's job API and Nova's tools           |

How a build runs:

1. Nova (or the studio page) calls `start_build` with the plan and any uploaded files. The app
   writes a job row.
2. The worker picks the job up, mints a short-lived access token for that teacher (the
   connector's OAuth tokens), and runs Codex with our `/mcp` as its only tool server.
3. Progress titles go to the job row. Nova reads them aloud ("writing lesson 2…").
4. Drafts appear in «مسوداتي». The teacher previews them and leaves notes by voice or on
   screen; `fix_notes` is another job on the same Codex session.

Where it runs: Cloudflare Pages cannot run a CLI, so the worker runs on a server. We chose the
VPS wp-slack-agent runs on, as its own user and folder (D11; setup in docs/builder-server.md).

What is built (Y6, Y7 first part):

- **Teachers:** the «اعمل كورس» page (`/?studio`): topic, up to 5 files (PDF, Word, images,
  text), the guide's "Ask first" choices as chips (learners, language, up to 3 teaching
  styles, boards, questions, size) and web search on or off. Then a progress screen with the
  builder's steps and a link to the first draft lesson. One build at a time, 10 a day.
- **App:** `build_jobs` and `build_files` (migration 0006); `/api/studio/jobs` for teachers;
  `/builder/*` for the worker, behind the `BUILDER_TOKEN` secret. The worker pulls jobs, so
  the server opens no port. Each job gets a one-hour `/mcp` token for its teacher, and the app
  writes the prompt (`server/builds/request.ts`), so the worker holds no product logic.
- **Worker:** `workers/builder/` (Node built-ins only): converts PDF and Word to text, runs
  `codex exec --json` with `/mcp` as `newlearn`, turns its events into Arabic steps, resumes
  once after a dropped stream, and reports the result. A job left running 45 minutes goes back
  to the queue once, then fails.
- **Side chat (S2, 2026-10-31):** on a draft (`?draft=<lesson>`), «عدّل بالكلام» opens a chat.
  The teacher says what to change; that is a build job of its own kind (`request.refine`:
  course, lesson, revision and the teacher's language), charged `lesson.refine` (3 credits).
  Its prompt (`server/builds/refine.ts`) limits the worker to that one lesson
  (`get_lesson`, `update_lesson`, `put_board`), and the teacher's words cannot change the
  rules. The panel shows the steps; every few seconds the page checks the lesson, and a new
  revision or board reloads the preview on the step the teacher was on. The job is done when
  the lesson changed while it ran; otherwise it fails with the worker's own reason and the
  credits come back. One job at a time per teacher, and 40 edits a day besides the 10 builds.
  Routes: `POST`/`GET /api/studio/lessons/<id>/edits`; the studio page's list leaves edits out.
- **Still to come:** Nova's `start_build` and `build_status`, skills (Y9), API keys for customers (Y13) and usage limits per plan (Y10). Voice
  choice is not on the page yet: lessons have no recorded voice until OR24.

## Cost and terms (must hold)

- **Paying customers' jobs use API keys:** Anthropic Console or OpenAI Platform, billed per token.
  - Anthropic's Agent SDK docs allow Free, Pro and Max sign-in only in Claude Code and Claude.ai
    themselves; products must use API keys.
  - OpenAI recommends API keys for unattended Codex runs.
  - wp-slack-agent signs Codex in with a ChatGPT plan. That is fine for our own team's work, not
    for serving customers. Switching is configuration (environment), not code.
- **Our own content stays cheap:** Owner and Ess write curricula with Claude Code or Codex on
  their own plans, in learn-curriculums, as today.
- **Teachers' own AI stays free for us:** the connector lets a teacher use their own Claude or
  ChatGPT.
- **Every paid plan includes a number of builds and voice minutes:** usage is metered per user
  (tasks Y10, Y11).

## Lessons with real audio (OR24)

Today Nova reads a lesson through the Live session, which is paid per learner per minute.
Instead, each step gets its audio once, from Gemini TTS in Nova's own voice, at export time.
The file is stored by hash on R2 (F7), and every learner after that plays the same file.

- **When Live speaks:** only when the learner talks, to ask, answer or give a command. An open
  Live session costs almost nothing while it is silent.
- **Rough cost (estimate of 2026-10-28; check Google's own price page before relying on it):**
  - TTS: about $10–20 per million audio tokens. At 25 tokens per second, a 15-minute lesson
    costs about $0.25–0.45 once, whatever the number of learners.
  - Live reading: about $0.27 or more per learner for the same lesson, and the cost grows with
    the conversation context.
- **Risks to test first (Y15):**
  - Egyptian Arabic mixed with English, and maths read aloud; the text is made speakable
    before TTS, as the Live instruction does today.
  - The hand-over between a step's audio file and a Live reply in the same voice.

## Live session limits to handle

Gemini Live sessions have a maximum length and send `goAway` before closing; today a dropped
session reopens with a short primer. Y3 adds session resumption and context compression, so a
long study session continues without losing the conversation. Check the current Live API
limits when building Y3.
